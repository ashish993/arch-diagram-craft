Cloud architecture: media processing

A workload view for solution architects and platform engineers: what enters the cloud, which services handle it, where data persists, and how asynchronous work is observed.

Fictional teaching example. Cloud account, provider, regions, managed service choices, identity, network controls, redundancy, and security configuration are not specified. The boundary is conceptual; it is not evidence of deployed controls.

Reading this view

Follow the synchronous submission path first, then trace the separate asynchronous processing path from queue to worker. The metadata store and object stores hold different kinds of state.

  • Solid arrows show the labeled request, state, and object movement.
  • The queue-to-worker path is asynchronous; it does not imply delivery guarantees.
  • Provider logos and unsupported security claims are intentionally omitted.
