Selection rationale

Choose the diagram for the question.

The example gallery covers recurring diagram forms used to explain system scope, runtime structure, interactions, deployment placement, and business work. These sources establish recognized notations and use cases; they do not provide a comparable frequency survey across solution architects, developers, and business users.

How to read this page: this is a practical cross-audience selection, not a statistical ranking of diagram popularity.

The diagrams in this repository are original, fictional HTML/SVG teaching examples. The sources inform the choice of view; their text and diagrams have not been copied. Each example includes notes that identify its assumptions and evidence gaps.

What diagram tools suggest

  • Structurizr: define an architecture model once and produce multiple C4 views. The skill now recommends a shared element and relationship inventory when the same system appears in multiple views, so names and boundaries do not drift.
  • Mermaid and PlantUML: use text sources to generate diagrams. This makes changes easier to review and reproduce, but a generated layout still needs a semantic and visual check.
  • draw.io / diagrams.net: preserve an editable graph model alongside rendered outputs. The skill now asks authors using visual editors to retain the native file and confirm that it reopens or reimports.

These tools are options, not required dependencies. The skill keeps its acceptance checks independent of the authoring tool: confirm evidence, abstraction, endpoints, branch meaning, accessibility, and the exact rendered artifact.
